### Component 2: TenantResolutionFilter (Request Interceptor)

**File:** `modules/core-platform/src/main/java/villagecompute/storefront/tenant/TenantResolutionFilter.java`
**Lines:** 308
**Status:** ✅ Production-Ready

**Features:**
1. **JAX-RS ContainerRequestFilter** at `AUTHENTICATION - 1` priority (runs before auth)
2. **Dual resolution strategy:**
   - First: Check `custom_domains` table by full domain
   - Fallback: Extract subdomain from `Host` header, check `tenants` table
3. **Caffeine cache integration:**
   - Cache key: hostname (lowercase)
   - Cache size: 1000 entries
   - TTL: 5 minutes (configurable via `quarkus.cache.caffeine."tenant-cache".expire-after-write`)
   - Cache miss triggers database lookup
4. **Tenant status validation:**
   - `active` → Allow request
   - `suspended` → HTTP 503 Service Unavailable
   - `deleted` → HTTP 404 Store Not Found
5. **PostgreSQL RLS session variable seeding:**
   - Calls `SELECT set_config('app.tenant_id', ?, false)` before query execution
   - Ensures all queries respect RLS policies
6. **CDI event publishing:**
   - `TenantResolved` event on successful resolution
   - `TenantMissing` event on 404
7. **Structured logging:**
   - OpenTelemetry span attributes (`tenant.id`, `tenant.subdomain`)
   - SLF4J info/warn logging for resolution success/failure
8. **Configuration toggles:**
   - `tenant.rls.enabled` - Enable/disable RLS session variable (default: true)
   - `tenant.cache.enabled` - Enable/disable caching (default: true)

**Resolution Flow:**
```
HTTP Request → Extract Host header → Normalize (lowercase, strip port)
              ↓
Cache lookup by hostname
              ↓
    ┌─────────┴─────────┐
    Cache HIT          Cache MISS
         ↓                  ↓
    TenantInfo      Database lookup:
                    1. Check custom_domains by domain
                    2. Else extract subdomain, check tenants
                         ↓
                    Found? → Cache + return
                    Not found? → HTTP 404
              ↓
Validate status: active/suspended/deleted
              ↓
Seed PostgreSQL session variable (RLS)
              ↓
Store in TenantContext ThreadLocal
              ↓
Fire TenantResolved CDI event
              ↓
Continue request processing
```

**Error Handling:**
- Missing `Host` header → HTTP 400 Bad Request
- Unknown domain → HTTP 404 Store Not Found
- Suspended tenant → HTTP 503 Service Unavailable
- Database errors → Logged, HTTP 500 (exception propagates)

### Component 3: TenantContextClearFilter (Cleanup)

**File:** `modules/core-platform/src/main/java/villagecompute/storefront/tenant/TenantContextClearFilter.java`
**Status:** ✅ Production-Ready

**Purpose:** Prevent ThreadLocal memory leaks by clearing `TenantContext` after response completion.

**Implementation:**
- JAX-RS `ContainerResponseFilter` (runs after request completes)
- Calls `TenantContext.clear()` in `finally` block
- No exceptions thrown (fail-safe cleanup)

**Why This Matters:**
- ThreadLocals persist in servlet thread pools
- Without cleanup, threads retain tenant context from previous requests
- Leakage can cause cross-tenant data access bugs

2. **RLS Policies Applied to 25+ Tables:**
   - **Tenancy Module:** tenants, custom_domains
   - **Identity Module:** users, roles, user_roles, api_keys
   - **Catalog Module:** categories, products, product_variants, product_images, inventory_levels
   - **Cart/Order Module:** carts, cart_items, orders, order_line_items, shipments

   - **Consignment Module:** consignors, consignment_items, payout_batches, payout_line_items
   - **Loyalty Module:** loyalty_programs, loyalty_members, loyalty_transactions

3. **Policy Template:**
```sql
ALTER TABLE <table_name> ENABLE ROW LEVEL SECURITY;
ALTER TABLE <table_name> FORCE ROW LEVEL SECURITY;

CREATE POLICY <table>_isolation_policy ON <table_name>
    FOR ALL
    USING (tenant_id = get_current_tenant_id());
```

**Key Features:**
- `FORCE ROW LEVEL SECURITY` - Applies RLS even to table owner (defense-in-depth)
- `FOR ALL` - Policy applies to SELECT, INSERT, UPDATE, DELETE
- `USING (tenant_id = get_current_tenant_id())` - Only match rows for current tenant

**Rollback Support:**
