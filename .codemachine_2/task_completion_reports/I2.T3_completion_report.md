## API Design Patterns Implemented

### 1. Tenant Context Resolution
- All endpoints automatically resolve tenant from Host header
- No explicit tenant_id parameter in URLs
- TenantContext.getCurrentTenantId() used throughout
- RLS enforcement at database level

### 2. Feature Flag Integration
- Catalog search: `catalog.search.enabled` (ProductResource:131)
- Variant matrix: `catalog.variant-matrix.enabled` (ProductResource:208)
- Import/export: `catalog.import-export.enabled` (spec)

### 3. RFC 7807 Problem Details
- Consistent error response format
- type, title, status, detail fields
- Used across all error responses

### 4. Rate Limiting
- Anonymous: 100 req/min
- Authenticated: 1000 req/min
- Headers: X-RateLimit-Limit, X-RateLimit-Remaining, X-RateLimit-Reset
- Defined as reusable header components

### 5. Pagination Contract
- Query params: page (1-indexed), pageSize (default 20, max 100)
- Response metadata: page, pageSize, totalItems, totalPages, hasNext, hasPrev
- Used by: product list, collection list

### 6. Async Job Pattern
- 202 Accepted response for long-running operations
- Job ID returned for tracking
- Webhook or polling for completion
- Used by: import/export endpoints
