### ✅ Criterion 4: Docs describing payout sweep logic

**Evidence:**
- **Primary Documentation:** `docs/consignment-payout-ledger.md` (lines 202-245)
  - **Automated Sweep Algorithm**
    - Feature flag: `consignment.payout.auto_sweep.enabled`
    - Config: min_balance ($50), period (weekly/monthly)
  - **Sweep Steps:**
    1. Query eligible consignors (available_balance >= min)
    2. For each consignor, emit `ConsignmentPayoutDue` event
    3. Create PayoutBatch with line items
    4. Initiate Stripe Connect payout
    5. Record payout in ledger, decrement available balance
  - **Error Handling:**
    - Insufficient balance: Skip consignor, log warning
    - Stripe API failure: Mark batch as 'failed', retry with exponential backoff
  - **Idempotency:** Batch creation prevents duplicates via unique constraint
- **Settlement Flow:** (lines 76-114)
  - Daily job moves pending → available after hold period (default: 7 days)
  - Uses `PayoutLedgerService.settlePendingToAvailable()`
- **Monitoring/Alerts:** (lines 481-489)
  - Negative balance detection
  - Settlement lag alerts
  - Payout failure alerts
  - Balance mismatch reconciliation

**Diagrams Included:**
- Sale flow with ledger update
- Settlement flow (pending → available)
- Refund flow (available → pending deduction)
- Payout flow with Stripe integration
